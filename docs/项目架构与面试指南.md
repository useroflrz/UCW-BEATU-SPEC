# BeatU 项目架构与面试指南

> 本文档整合项目架构、文件结构、代码理解，以及面试重难点、创新点与 Android 开发知识点。

---

## 一、项目架构总览

### 1.1 整体架构模式

```
┌─────────────────────────────────────────────────────────────────┐
│                     BeatU 项目 (UCW-BEATU-SPEC)                   │
├──────────────────┬──────────────────┬──────────────────────────┤
│   BeatUClient    │   BeatUBackend    │   AgentMCP (可选)         │
│   Android 客户端 │   FastAPI 后端     │   智能体子模块            │
│ Kotlin + Jetpack │ Python + MySQL    │                          │
└──────────────────┴──────────────────┴──────────────────────────┘
```

### 1.2 客户端架构：Clean Architecture + MVVM

```
Presentation (UI + ViewModel)
      ↓ 调用
Domain (UseCase + Repository 接口)
      ↓ 实现
Data (Repository 实现：Remote + Local 数据源)
```

- **Presentation**：Jetpack ViewModel、StateFlow/LiveData、Navigation、Fragment
- **Domain**：UseCase、Repository 接口，纯 Kotlin、可单元测试
- **Data**：API Service、RemoteDataSource、LocalDataSource、Mapper、Repository 实现

## 三、数据流与设计模式

### 3.1 数据流示例：获取视频列表

```
ViewModel.loadVideoList()
    → GetFeedUseCase(page, limit)
    → VideoRepository.getVideoFeed()
    → VideoRepositoryImpl:
        1. 先 emit(本地缓存) 若存在
        2. 调用 RemoteDataSource.getVideoFeed()
        3. 保存到 LocalDataSource
        4. emit(远程数据)
```

### 3.2 使用的设计模式

| 模式 | 应用场景 |
|------|----------|
| **策略模式** | 播放器内核可切换（VideoPlayer 接口）、清晰度选择 |
| **工厂模式** | PlayerPool 创建 ExoVideoPlayer、Repository 创建 |
| **观察者模式** | StateFlow 驱动 UI、播放状态监听 |
| **适配器模式** | DTO → Domain 映射、不同数据源统一接口 |
| **建造者模式** | ExoPlayer 配置、OkHttp 配置 |
| **插件式架构** | AI 能力模块、播放器内核扩展 |

### 3.3 依赖注入（Hilt）

- `@HiltAndroidApp` 在 BeatUApp
- `@AndroidEntryPoint` 在 Activity/Fragment
- `@HiltViewModel` 在 ViewModel
- 各模块 `*DataModule` 提供 Repository、DataSource、ApiService

## 四、技术实现亮点

### 4.1 播放器与性能

- **VideoPlayer 抽象层**：`shared/player/VideoPlayer.kt`，支持未来切换 ExoPlayer/ijkplayer
- **PlayerPool**：`VideoPlayerPool.kt`，限制 2~3 实例，配合 ViewPager2 offscreenPageLimit 预加载
- 目标指标：首帧 <500ms、播放成功率 ≥99%、卡顿率 <2%

### 4.2 认证与会话

- **AuthSessionStore**：SharedPreferences 持久化 userId、userName、accessToken
- **BeatUApp.onCreate**：`authSessionStore.loadToMemory()` 启动时装载
- **HeaderInterceptor**：自动注入 `Authorization: Bearer {token}`
- **UnauthorizedRedirectInterceptor**：401 清空会话并跳转 AuthActivity

### 4.3 深度链接

- `beatu://video/{id}` → 拉取视频详情，打开 UserWorksViewerFragment 播放
- `beatu://user/{id}` → 打开用户主页
- `beatu://ai/hot?q=...` → AI 话题召回
- 分享链接使用 `beatu://video/{id}`，点击可唤起 App

### 4.4 存储监控

- **StorageMonitor**：`StatFs` 检测内部存储，阈值 2GB
- **StorageLowNotifyHelper**：低空间时通知提醒
- 启动时 `BeatUApp` 检查并注册 BroadcastReceiver

### 4.5 网络预取

- **ConnectivityObserver**：WiFi / 移动网络 / 无网
- 推荐流预取：WiFi 提前 2 页、移动网络 1 页、无网不预取

### 4.6 跨模块路由

- **RouterRegistry**：注册 `UserProfileRouter`、`VideoItemRouter`
- 解决 videofeed ↔ user 等模块循环依赖

## 六、面试重难点与创新点

### 6.1 重难点

| 难点 | 说明 | 对应实现 |
|------|------|----------|
| **播放器生命周期** | ViewPager2 滑动时 Fragment 创建/销毁，播放器需正确 attach/detach | VideoItemViewModel 管理 PlayerPool.acquire/release，onParentVisibilityChanged 暂停 |
| **横屏返回竖屏** | Surface 重建导致画面丢失 | configChanges、onConfigurationChanged 恢复 PlayerView |
| **嵌套滚动** | ViewPager2 垂直滑动 + 下拉刷新 + 倍速调节手势 | 触摸事件分发、requestDisallowInterceptTouchEvent |
| **无限循环 Feed** | 滑到底部继续浏览 | hasLoadedAllFromBackend 时 getItemCount 返回 Int.MAX_VALUE，取模定位 |
| **401 统一处理** | 多处接口可能返回 401 | UnauthorizedRedirectInterceptor 拦截，清空 Token 并跳转登录 |
| **模块解耦** | videofeed 需跳转 user 模块 | RouterRegistry 注册 Router，依赖注入 |
| **缓存一致性** | 本地缓存与远程数据 | 先展示本地，后台拉取远程，成功后更新并保存 |
| **关注流过滤** | 仅展示已关注作者视频 | 后端 channel=follow + UserFollow 表 JOIN |

### 6.2 创新点

| 创新点 | 说明 |
|--------|------|
| **AI 与短视频融合** | AI 搜索流式返回、评论区 @元宝 问答、清晰度建议 |
| **播放器池复用** | 固定实例数，减少内存与创建开销 |
| **网络感知预取** | WiFi/移动/无网不同预取策略 |
| **深度链接闭环** | 分享链接可直达 App 内视频播放 |
| **存储空间预警** | 2GB 阈值提醒，避免写入失败 |
| **图文 + 视频混编** | Feed 支持 IMAGE_POST 类型（多图 + BGM） |
| **倍速手势** | 竖屏左右滑动调节倍速 |

## 七、面试可能问到的 Android 知识点

### 7.1 架构与 Jetpack

- **MVVM**：ViewModel 与 View 职责分离，StateFlow 驱动 UI
- **Clean Architecture**：Domain 不依赖 Data，依赖倒置
- **LiveData vs StateFlow**：StateFlow 冷流、可配置 replay，LiveData 生命周期感知
- **Navigation**：NavController、NavGraph、传参 bundleOf
- **Hilt**：@Inject、@Module、@Binds、@Provides、作用域 @ActivityScoped 等

### 7.2 生命周期

- **Activity/Fragment 生命周期**：onCreate → onStart → onResume → onPause → onStop → onDestroy
- **ViewModel 生命周期**：与 Activity/Fragment 绑定，配置变化不销毁
- **viewLifecycleOwner**：Fragment 中观察 Flow 应使用 viewLifecycleOwner
- **configChanges**：orientation 防止重建，自行处理 onConfigurationChanged

### 7.3 网络与数据

- **Retrofit**：接口定义、@GET/@POST、@Query/@Path/@Body
- **OkHttp Interceptor**：添加 Header、401 统一处理
- **Room**：Entity、Dao、Database、迁移
- **DataStore**：替代 SharedPreferences，支持 Flow
- **Kotlin Flow**：collect、catch、map、flatMapLatest

### 7.4 UI 与布局

- **ViewPager2**：基于 RecyclerView，垂直滑动、offscreenPageLimit
- **RecyclerView**：Adapter、ViewHolder、DiffUtil
- **ConstraintLayout**：相对约束、Guideline
- **ViewBinding**：替代 findViewById

### 7.5 多媒体

- **ExoPlayer/Media3**：Player、MediaItem、PlayerView、监听器
- **Surface/SurfaceView**：视频渲染、attach/detach
- **音视频同步**：ExoPlayer 内置处理

### 7.6 并发与线程

- **Coroutine**：launch、async、Dispatchers.Main/IO、withContext
- **Flow**：冷流、collect、channel
- **runBlocking 使用场景**：兼容旧代码的桥接，慎用

### 7.7 性能与内存

- **内存泄漏**：Fragment/Activity 引用、Listener 未移除
- **LeakCanary**：检测泄漏
- **Bitmap 回收**：及时 recycle，大图压缩
- **Profiler**：CPU、内存、网络分析

### 7.8 其他

- **Deep Link**：intent-filter、scheme、host、pathPrefix
- **FileProvider**：分享文件、Android 7+ 安全
- **权限**：运行时权限、RECORD_AUDIO、CAMERA
- **多模块依赖**：api vs implementation、循环依赖解决
